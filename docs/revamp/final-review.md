## 4. 分期規劃合理性

### 4.1 Phase 依賴正確性

```
Phase 1（信任+修復）
  S1 審核標記 ── 獨立
  S2 TBT 優化 ── 獨立
  S3 Mode 修復 ─┐
  S4 eu_reg 修復─┤─→ S5 REVIEW_NEEDED 清理
                └──（S5 部分依賴 S3、S4 的修復結果）

Phase 2（留存+體驗）── 依賴 Phase 1 完成
  S6 RSS Feed ──→ S8 首頁（整合訂閱入口）
  S7 合規時程 ── 獨立
  S9 About 頁 ── 依賴 S1（審核標記就緒）

Phase 3（差異化）── 依賴 Phase 2 完成
  S10 跨框架比較 ── 獨立
  S11 iso 分類 ── 獨立
  S12 eu_reg 降權 ── 依賴 S4（資料源恢復後再降權）
  S13 責任追蹤 ── 獨立
  S14 動態目錄 ── 獨立
```

**評估**：依賴關係合理。Phase 1 聚焦基礎問題，Phase 2 建立在信任基礎上改善體驗，Phase 3 在穩定系統上追求差異化。

### 4.2 Phase 1 範圍風險

| 項目 | 風險評估 |
|------|----------|
| S1 審核標記 | 低風險——純文件修改 |
| S2 TBT 最後 10ms | 中風險——210→200ms 可能需要多次嘗試；策略已備有 A/B/C 三個方案 |
| S3 Mode 修復 | 中高風險——根因尚不明確，可能是 Qdrant 查詢、資料不足或邏輯錯誤 |
| S4 eu_regulations 修復 | 中風險——外部依賴（EUR-Lex RSS），備援方案（CELLAR API）增加複雜度 |
| S5 REVIEW_NEEDED 清理 | 低中風險——工作量大但可預測（45 份逐一審核） |

**結論**：Phase 1 包含 5 個 P0 項目，範圍偏大但都是基礎問題。建議 S1 和 S2 可立即平行執行，S3 和 S4 需先診斷根因再行動，S5 在 S3/S4 部分完成後啟動。

## 5. 綜合評估

### 優點

1. **邏輯鏈條完整**：從品牌定位到內容規格的 9 條邏輯鏈路全部貫穿，無斷裂——這在改版分析中非常少見
2. **數據驅動**：所有發現都有工具數據佐證（Lighthouse、W3C Validator、grep 統計），非主觀判斷
3. **前後版對比清楚**：每個階段都與 2026-02-19 前版比較，清楚呈現一個月來的進展（TBT -68%、Performance +12）和未改善項目
4. **優先級一致**：P0/P1/P2 分級在 6 個階段文件中保持高度一致，僅少數合理調整
5. **追溯表完整**：策略和規格都有追溯表，每個行動項都能回溯至差距分析或競品發現
6. **規格書操作性強**：S1-A 有 HTML/CSS 代碼、S2 有三種優化策略、S6 有 _config.yml 設定——開發人員可直接執行
7. **風險管理到位**：策略包含 6 個風險評估和依賴分析，Phase 1 有備援方案

### 問題

1. **GA 追蹤規格缺失**：多數 KPI 基線為「未知」，但設定 GA 追蹤的技術規格未包含在規格書中

3. **品牌訊息 fallback 缺失**：若 S3 修復失敗，「7 份報告」承諾如何調整？
4. **監控機制規格不足**：S3 提到建立監控，但規格書未定義具體監控方案
5. **nist_frameworks 停滯未列入修復範圍**：8 個月無更新但未安排排查
