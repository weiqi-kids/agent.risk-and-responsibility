## 1. 受眾深度分析

### 1.1 主要受眾：企業 CISO / 資安主管

#### Persona 摘要

| 項目 | 描述 |
|------|------|
| 角色 | 中大型企業資安長或資安主管（需同時關注美國、歐盟、國際標準） |
| 年齡/背景 | 35-55 歲，技術背景，10+ 年資安經驗，管理跨國合規團隊 |
| 目標 | 確保組織合規，降低資安風險，在合規審查與董事會彙報中展現主動監控能力 |
| 痛點 | (1) 法規來源分散於 NIST、EU、ISO 等，人工追蹤每週耗費 4-8 小時；(2) 難以判斷哪些變動真正影響自身組織；(3) 缺乏結構化的「責任歸屬變化」追蹤機制 |
| 行為特徵 | 習慣週一早晨快速掃描摘要；重視可引用的結構化來源；偏好表格式呈現而非長篇文章 |

#### Jobs-to-be-Done

| 任務類型 | 具體任務 |
|----------|----------|
| 功能性 | 每週 15 分鐘內掌握全球法規變動全貌，快速評估對組織的影響並產出行動項目 |
| 情感性 | 感到掌控全局——不擔心遺漏重要變動，在不確定的監管環境中保持信心 |
| 社會性 | 在管理會議和董事會彙報中展現專業主動性，被視為「法規動態的掌握者」 |

#### 使用者旅程

| 階段 | 行為 | 問題/疑慮 | 需要的資訊 | 期望的體驗 |
|------|------|-----------|------------|------------|
| 意識 | 搜尋「NIST CSF 2.0 changes」「EU AI Act compliance tracker」 | 哪個來源可靠且持續更新？ | 權威來源彙整、更新頻率證明 | 一站式、專業外觀 |
| 考慮 | 瀏覽報告目錄，抽讀 1-2 份報告檢視深度和來源引用 | 這是 AI 自動生成的嗎？有人工審核嗎？ | 方法論說明、審核者資歷、更新歷史 | 可信、結構化、有出處 |
| 決策 | 加入書籤或訂閱 RSS/email | 值得每週花 15 分鐘嗎？能否直接引用？ | 報告價值證明（如「本週重點行動項」） | 低門檻訂閱、快速獲取價值 |
| 使用 | 每週一早上閱讀 Executive Summary，再深入特定 Mode | 哪些跟我的組織有關？行動優先級？ | 依角色/產業篩選、行動期限、影響評估 | 快速定位重點、可直接轉發給團隊 |
| 推薦 | 分享給資安團隊、法遵部門或同業社群 | 推薦一個 AI 生成的來源會影響我的專業形象嗎？ | 可引用格式、清晰的 AI 輔助+人工審核說明 | 易分享、有公信力 |

#### 資訊需求

| 想知道什麼 | 擔心什麼 | 需要的證據 |
|------------|----------|------------|
| 本週有哪些法規變動影響我們 | 遺漏重要更新導致合規風險 | 官方來源連結、enforcement_signal 分類 |
| 責任歸屬如何變化（誰要負責什麼） | 責任界定不清導致稽核問題 | shift_type + affected_roles 結構化資料 |
| 需要在何時採取行動 | 錯過合規期限 | 明確的 deadline、生效日期、過渡期 |
| 跨框架要求如何交互影響 | 滿足 A 框架卻違反 B 框架 | 跨框架對照分析 |

### 1.2 次要受眾：法遵 / 合規主管

#### Persona 摘要

| 項目 | 描述 |
|------|------|
| 角色 | 法務部門合規經理或法遵官 |
| 年齡/背景 | 30-50 歲，法律或商管背景，熟悉 GRC 工具 |
| 目標 | 確保組織符合所有適用法規，準備稽核文件，追蹤法規時程 |
| 痛點 | (1) 法規文字艱澀需要翻譯成行動項目；(2) 跨國法規複雜且互相關聯；(3) 需要可追溯的文件紀錄以應對稽核 |
| 行為特徵 | 重視細節、需要可追溯的文件、偏好結構化清單和時程表 |

#### Jobs-to-be-Done

| 任務類型 | 具體任務 |
|----------|----------|
| 功能性 | 追蹤法規變動並轉化為合規檢查清單；比對現有控制措施與新要求的差距 |
| 情感性 | 確信不會在稽核時被發現漏洞；安心地向主管回報「我們已掌握最新法規」 |
| 社會性 | 被視為組織內的法規專家，能在跨部門會議中提供精確的法規引用 |

#### 使用者旅程

| 階段 | 行為 | 問題/疑慮 | 需要的資訊 | 期望的體驗 |
|------|------|-----------|------------|------------|
| 意識 | 收到新法規通知或稽核要求，搜尋解讀資訊 | 哪裡有最完整的法規彙整？ | 法規全文連結 + 白話解讀 | 快速找到權威解讀 |
| 考慮 | 比對多個來源的解讀是否一致 | 這個 AI 生成的解讀準確嗎？ | 原文對照、不確定性標註 | 標註 [系統推論] 與已確認事實 |
| 決策 | 決定是否將本站納入日常追蹤工具 | 能否滿足我的稽核文件需求？ | 結構化輸出、可下載格式 | 可直接匯入 GRC 工具 |
| 使用 | 季度合規審查前回溯歷史變動 | 過去 3 個月有什麼我漏掉的？ | 按時間排序的完整變動紀錄 | 時間軸瀏覽、篩選功能 |
| 推薦 | 在法遵社群分享有用的追蹤工具 | 推薦後出錯會影響專業信譽 | 準確率、勘誤機制 | 有回報錯誤的管道 |

#### 資訊需求

| 想知道什麼 | 擔心什麼 | 需要的證據 |
|------------|----------|------------|
| 新法規的具體要求條文 | AI 解讀是否準確 | 原文連結 + [REVIEW_NEEDED] 標註 |
| 合規期限和過渡期 | 遺漏合規 deadline | 明確的日期和時程表 |
| 對現有控制措施的影響 | 控制措施不足以符合新要求 | 新舊要求差異比較 |

## 3. 問題根因分析

| 問題類型 | 具體問題 | 根因 | 影響範圍 | 解決方向 |
|----------|----------|------|----------|----------|
| **可信度不足** | 純 AI 署名，無人工審核 | 系統設計時以自動化為優先，未納入 E-E-A-T 考量 | 全站所有報告——YMYL 類內容的最大風險 | 建立人工抽樣審核機制；在每份報告加入審核者標記；About 頁面呈現完整方法論 |
| **產出不完整** | 5/7 Mode 有週報（ai_governance_landscape、ai_implementation_guide 僅月報） | 這兩個 Mode 的 Qdrant 查詢或報告產出邏輯可能有問題；或因資料源不足導致無法產出有意義的週報 | 品牌承諾「7 份報告」未兌現；系統穩定性受質疑 | 排查 Mode 執行日誌；評估是否將這兩個 Mode 調整為月報週期（並更新品牌訊息） |
| **產出中斷** | W10-W11 全部 Mode 無產出 | 可能為系統維護、執行錯誤或人為跳過 | 週報連續性斷裂，損害「每週更新」承諾 | 建立執行監控和告警機制；評估是否需要補產 W10-W11 報告 |
| **內容品質不一致** | 45 份 REVIEW_NEEDED 未清理 | 萃取邏輯遇到邊緣案例（制裁決議、缺乏來源的 CVE、非核心領域標準）時標記但未後續處理 | ai_governance_landscape 全部報告均標記，該 Mode 品質堪憂 | 批次審核並消除標記；將低關聯性內容歸檔或重新分類 |
| **資料源斷裂** | eu_regulations 自 W09 起無新資料 | EUR-Lex RSS 可能回傳空檔或 feed URL 變動 | 歐盟法規涵蓋中斷——佔總文件數 44% 的最大 Layer | 排查 fetch.sh；建立 RSS 監控；考慮備援抓取方式（CELLAR API、OJ 直接抓取） |
| **資料源老化** | nist_frameworks 最新文件 2025-07-22（8 個月前） | NIST 出版物發布頻率本就較低；或 fetch.sh 未正確抓取新發布 | 框架類內容可能遺漏重要更新 | 檢查 NIST RSS/API 是否有新發布；確認 fetch.sh 運作正常 |
| **分類精度不足** | iso_standards 67% 歸類為 "other" | 分類 enum 未涵蓋 ISO 標準的多樣性（品質管理、環境、能源等） | 語意搜尋精度下降；報告引用時分類資訊不足 | 細化 iso_standards 分類 enum；重新歸類現有文件 |
| **低關聯性內容稀釋** | eu_regulations 中 120 份 institutional_administration（制裁決議）與核心受眾需求關聯性低 | fetch 階段未充分過濾；EUR-Lex RSS 涵蓋所有歐盟立法 | 佔總文件數 14%，稀釋語意搜尋結果品質 | 在 fetch 階段加強過濾條件；或在 Qdrant 中降低這類文件的權重 |
| **導航限制** | 缺乏跨 Mode 搜尋和角色導向篩選 | Jekyll 靜態網站限制；Qdrant 搜尋僅用於系統內部 | 使用者找到特定內容的時間成本高 | 短期：加入 JS 篩選功能；中期：開放前端語意搜尋 |
| **留存機制缺失** | 無 RSS/email 訂閱功能 | 優先開發核心萃取和報告功能，訂閱功能延後 | 使用者必須手動回訪，回訪摩擦高 | 使用 jekyll-feed 外掛快速實作 RSS |

## 6. 關鍵發現摘要

### 最重要的 3 個發現

1. **E-E-A-T 可信度缺口仍是最大風險**：一個月過去仍未加入人工審核標記。本站是所有競品中唯一純 AI 產出的來源，在 YMYL 類內容領域這是 Google 排名和使用者信任的最大障礙。45 份 REVIEW_NEEDED 文件（其中 ai_governance_landscape 全部報告均標記）進一步惡化品質感知。→ **建議立即加入審核者資訊和方法論說明（P0）**

2. **品牌承諾與實際產出存在差距**：定位文件承諾「每週整合 7 大權威來源，產出 7 份結構化報告」，但實際上 (a) 僅 5/7 Mode 有週報，(b) W10-W11 全部中斷，(c) eu_regulations 自 W09 起無新資料，(d) Extractor 文件數一個月未成長。這會侵蝕「穩定自動化系統」的核心信譽。→ **建議排查並修復產出管線，或調整品牌訊息以符合實際能力（P0）**

3. **技術效能已大幅改善，重心應轉向內容和信任**：Performance 83→95（+12）、TBT 660→210ms（-68%）是顯著進步，但效能只是基礎。競品分析顯示，使用者選擇法規追蹤工具的核心考量是「可信度」和「可行動性」——而非頁面載入速度。→ **建議下階段策略從「技術修復」轉向「內容品質+信任建設+使用者留存」（P1）**

### 改版重點方向

基於以上分析，建議改版聚焦於以下四個方向（按優先級排序）：

1. **信任建設（P0）**：加入人工審核機制和 E-E-A-T 信號；清理 REVIEW_NEEDED 文件；強化方法論可見度
2. **產出穩定性（P0）**：修復 eu_regulations 資料源；確保 7/7 Mode 穩定產出；建立監控告警
3. **使用者留存（P1）**：實作 RSS/email 訂閱；加入合規時程和行動期限；改善導航和篩選
4. **差異化強化（P1-P2）**：責任追蹤視覺化；跨框架比較表；開放語意搜尋；PDF 下載
