## L1 — Rule Signal
- **rule_type**: amendment
- **issuing_body**: Cloud Security Alliance (CSA)
- **document_id**: HIPAA Security Rule NPRM（HHS OCR, 2024-12-27 發布）
- **status**: public_comment

## L2 — Responsibility Structure
- **affected_roles**: 醫療保健 CISO（主要受眾）、業務合作夥伴（Business Associates）、董事會/CEO、IT/合規/法務/安全團隊、第三方供應商
- **shift_type**: expanded
- **shift_summary**: HIPAA 安全規則二十多年來首次重大修訂，將幾乎所有實施規範改為強制性，並要求從文件意圖轉向實際運作驗證，醫療 CISO 需立即啟動運作重新設計而非等待最終規則發布

## L3 — Risk Domains
- 合規框架（HIPAA Security Rule 全面修訂）
- 雲端安全（ePHI 的加密、網路分隔、多因素驗證等技術控制）
- 最佳實踐（漏洞掃描半年一次、滲透測試每年一次）

## L4 — Obligation & Evidence
- **new_obligations**:
  - 多因素驗證、靜態與傳輸中加密、網路分隔、防惡意軟體保護成為明確要求
  - 72 小時資料還原程序
  - 每六個月漏洞掃描、每年滲透測試（由合格專業人員執行）
  - 業務合作夥伴須透過主題專家分析和書面認證年度驗證技術保障措施
  - 建立持續 ePHI 系統清單與資料流圖
  - 第三方風險管理的以證據為基礎的工作流程
  - 準備任何控制的兩年證據追蹤
- **evidence_requirements**:
  - 完整且最新的 ePHI 系統清單含資料流圖
  - 書面認證取代問卷式的業務合作夥伴認證
  - 正式滲透測試文件（含範圍和結果）
  - 所有必要控制持續運作的證明（非僅文件化）
- **enforcement_signal**: mandatory
